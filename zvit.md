## Відповіді на питання самоконтролю. Частина 1

1. **Що таке HTML і для чого він використовується?**
   HTML (HyperText Markup Language) — стандартна мова розмітки для документів,
   що відображаються у веббраузері. Визначає структуру та вміст вебсторінки за
   допомогою тегів. Використовується для створення вебсторінок і вебзастосунків.

2. **Яка структура типової HTML-сторінки? Які теги обов'язкові?**
   Структура: `<!DOCTYPE html>` → `<html>` → `<head>` (метадані) + `<body>`
   (видимий вміст). Обов'язкові: `<!DOCTYPE html>`, `<html>`, `<head>`,
   `<title>`, `<body>`. Рекомендований у `<head>`: `<meta charset="UTF-8">`.

3. **Різниця між блоковими та рядковими елементами.**
   Блокові займають усю доступну ширину і починаються з нового рядка
   (`div`, `p`, `section`, `h1`–`h6`, `ul`, `header`, `footer`). Рядкові
   займають ширину за вмістом і не переносяться на новий рядок
   (`span`, `a`, `strong`, `em`, `img`).

4. **Що таке семантичні теги і чому вони важливі?**
   Це теги, що описують зміст/призначення вмісту (`header`, `nav`, `main`,
   `section`, `article`, `aside`, `footer`). Важливі для доступності
   (скрін-рідери), SEO, читабельності та підтримки коду.

5. **Різниця між обов'язковими та необов'язковими атрибутами.**
   Обов'язкові потрібні для роботи елемента (`src`, `alt` у `<img>`, `href` у
   `<a>`). Необов'язкові — додаткові (`title`, `target`, `id`, `class`,
   `rel`). Відсутність необов'язкових не ламає елемент.

6. **Для чого тег `<meta>` і які атрибути може містити?**
   Надає метадані про документ, розміщується в `<head>`. Атрибути: `charset`,
   `name` (description, keywords, author, viewport), `content`, `http-equiv`,
   `property`. Використовується для кодування, SEO, адаптивності, соцмереж.

7. **Як працює тег `<link>` і які ресурси підключає?**
   Підключає зовнішні ресурси до документа. Атрибути `rel`, `href`, `type`.
   Підключає CSS, фавікон, шрифти, `preload`, `canonical`, RSS (`alternate`).

8. **Різниця між абсолютними та відносними посиланнями?**
   Абсолютне містить повний URL (`https://site.com/page`). Відносне — шлях
   щодо поточної сторінки (`/about`, `../img/a.png`). Відносні зручні для
   внутрішніх ресурсів і працюють незалежно від домену.

9. **Для чого атрибут `alt` у `<img>`?**
   Альтернативний текст: показується, якщо зображення не завантажилось,
   озвучується скрін-рідерами (доступність), покращує SEO та досвід за
   повільного з'єднання.

10. **Як правильно додати фавікон?**
    У `<head>`: `<link rel="icon" type="image/svg+xml" href="/favicon.svg">`
    (або `.png`, `.ico`). Також можна покласти `favicon.ico` у корінь сайту.
    Можна задати кілька розмірів/форматів окремими `<link>`.

11. **Які основні теги використовуються у формах?**
    `<form>`, `<input>`, `<label>`, `<textarea>`, `<select>`/`<option>`,
    `<button>`, `<fieldset>`/`<legend>`, `<datalist>`, `<output>`.

12. **Які існують типи полів введення (`input type`)?**
    `text`, `password`, `email`, `number`, `tel`, `url`, `date`, `time`,
    `search`, `checkbox`, `radio`, `file`, `range`, `color`, `hidden`,
    `submit`, `reset`, `button`.

13. **Навіщо атрибути `name`, `value`, `placeholder`, `required`?**
    `name` — ключ, під яким дані надсилаються на сервер; `value` — початкове
    значення поля; `placeholder` — підказка всередині поля; `required` —
    обов'язковість заповнення (клієнтська валідація).

14. **Чому `<label>` корисні і важливо їх використовувати?**
    Пов'язує підпис із полем (через `for`/`id` або вкладення): клік по підпису
    фокусує поле, покращується доступність (скрін-рідери) та зручність
    користувача, зростає площа кліку.

15. **Як працюють методи GET і POST у формах?**
    GET додає дані до URL (рядок запиту): видно у адресі, обмежений розмір,
    кешується — для пошуку/фільтрів. POST передає дані в тілі запиту: не видно
    в URL, без жорсткого обмеження розміру — для створення/зміни даних,
    авторизації.

16. **Що таке валідація форми на клієнті та на сервері?**
    Клієнтська — у браузері до відправки (HTML-атрибути, JS): швидкий фідбек,
    але її можна обійти. Серверна — на сервері: обов'язкова та надійна,
    остання лінія захисту даних.

17. **Як правильно розміщувати заголовки `<h1>`–`<h6>`?**
    Один `<h1>` на сторінку (головна тема), далі `<h2>` для розділів, `<h3>`
    для підрозділів тощо — без пропуску рівнів, з дотриманням логічної
    ієрархії.

18. **Які теги використовуються для відео та аудіо?**
    Відео — `<video>` (з `<source>`; атрибути `controls`, `autoplay`,
    `muted`, `loop`, `poster`). Аудіо — `<audio>` (`controls`, `loop`).
    Кілька `<source>` — для різних форматів.

## Відповіді на питання самоконтролю. Частина 2

1. **Що таке React і яке його основне призначення?**
   React — бібліотека JavaScript (від Meta) для побудови користувацьких
   інтерфейсів, переважно SPA. Призначення — декларативне створення UI з
   компонентів та ефективне оновлення DOM.

2. **Що таке Компонент у React?**
   Незалежний, багаторазовий фрагмент UI — функція, що повертає JSX. Може
   приймати `props` і мати власний стан.

3. **Що таке JSX? Чим відрізняється від HTML?**
   JSX — синтаксичне розширення JavaScript, схоже на HTML. Відмінності:
   атрибути у camelCase (`className`, `htmlFor`), вирази у `{}`, один
   кореневий елемент, усі теги мають бути закриті, компілюється в JS.

4. **Що складає валідний компонент React?**
   Функція з назвою з великої літери, що повертає JSX (один кореневий елемент
   або фрагмент) і експортується; може приймати `props`.

5. **Як передавати дані між компонентами?**
   Зверху вниз — через `props` (атрибути в JSX, читаються в параметрах
   дочірнього компонента). Зворотний зв'язок — через функції-колбеки,
   передані як `props`.

6. **Яка роль `main.jsx` та `App.jsx`?**
   `main.jsx` — точка входу: створює корінь (`createRoot`) і рендерить
   `<App />` у `#root`. `App.jsx` — головний (кореневий) компонент, який
   композиціює решту компонентів.

7. **Чому важливо розбивати інтерфейс на компоненти?**
   Повторне використання, ізоляція логіки, простіше тестування й підтримка,
   паралельна робота над частинами, читабельність.

8. **Що таке віртуальний DOM (Virtual DOM)?**
   Легка JS-копія реального DOM. React рендерить у неї, порівнює стару й нову
   версії (diffing) та оновлює лише змінені частини реального DOM — швидко й
   ефективно.

9. **Як вивести динамічні дані в JSX?**
   У фігурних дужках: `{value}`, `{arr.map(...)}`, `{obj.name}`, тернарний
   оператор тощо. Значення автоматично екрануються, що захищає від XSS.
